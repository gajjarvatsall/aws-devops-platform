# CloudOps Demo AWS DevOps Platform

Production-style Terraform and Flask reference infrastructure for a technical
assessment. **This repository has not deployed AWS infrastructure and contains
no credentials or live HTTPS endpoint.**

## Stack and layout

Terraform modules cover networking, security/IAM, RDS + Secrets Manager, S3,
ECR, and ALB/EC2 Auto Scaling. `environments/dev`, `staging`, and `prod`
provide isolated state keys and sizing. `app/` is a Python 3.12 Flask service
packaged with Gunicorn. `.github/workflows/` provides application CI,
Terraform validation, and a manually initiated OIDC deployment workflow.

## Local checks

```bash
python3 -m pip install -r app/requirements.txt
make test
make lint
make docker-build
make terraform-fmt
make terraform-validate
make security-scan
```

No local command runs `terraform apply`, `terraform destroy`, AWS CLI, or
resource provisioning. If a required tool is not installed, the command is
reported as skipped rather than represented as successful.

## AWS preparation and first deployment

Follow [docs/deployment-guide.md](docs/deployment-guide.md). Bootstrap the
encrypted/versioned S3 state bucket first, configure partial backends for the
distinct `dev/`, `staging/`, and `prod/` keys, and supply `terraform.tfvars`
locally. The operator must provide a real region, globally unique bucket name,
regional ALB account ID, and a same-region DNS-validated ACM certificate ARN.
A public URL requires a domain controlled by the operator; this project never
invents one.

Keep dev capacity at zero for the base apply, push an immutable ECR image,
then apply the desired capacity and image tag. Review the plan before every
apply. Production should use a separate AWS account, protected GitHub
environment, required reviewers, and a dedicated OIDC role.

## GitHub settings

Create environment variables `AWS_REGION`, `AWS_DEPLOY_ROLE_ARN`,
`TF_STATE_BUCKET`, and `TF_STATE_REGION`. Set `AWS_DEPLOY_ROLE_ARN` to a
dedicated role whose OIDC trust restricts `repo:ORG/REPOSITORY` and the
approved branch/environment. Configure production reviewers. No static AWS
access keys or secret values are needed by workflows.

## Known limitations and checklist

Before deployment: confirm provider/engine versions in the target region,
replace backend placeholders, select a current ALB regional account ID,
request/validate ACM DNS records, create the tightly scoped GitHub OIDC role,
review IAM/S3 policies, choose NAT topology, and set production protections.
The application secret is generated by Terraform and therefore exists in
state; state access must be treated as sensitive.

See [docs/operations-runbook.md](docs/operations-runbook.md) and
[SECURITY.md](SECURITY.md) for operational and reporting guidance.
